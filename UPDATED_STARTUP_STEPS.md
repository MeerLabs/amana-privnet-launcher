# Updated Startup Steps for Amana PoA Private Network (QNG v2.3.0+dev)

This document records the steps and adjustments required to run the Amana PoA private network using the latest QNG version (v2.3.0+dev).

During testing of the amana-privnet-launcher script, several compatibility issues were identified with the newer QNG version. The fixes and updated startup procedure are documented here so that the setup can be reproduced easily.

## Goal

The goal is to launch a 3-node Amana Proof-of-Authority (PoA) private network using the launcher script and verify that the nodes connect successfully through the P2P network.

## Environment

Operating System: Ubuntu (Virtual Machine)
QNG Version: 2.3.0+dev
Launcher Repository: amana-privnet-launcher
Python Version: Python3

## Installing Python Dependencies

Create a Python virtual environment:

python3 -m venv launcher-env

Activate the environment:

source launcher-env/bin/activate

Install the dependencies listed in requirements.txt:

pip install -r requirements.txt

The requirements.txt file installs the following dependencies required by the launcher script:

- eth-account
- starkbank-ecdsa

## Running the Launcher Script

Go  to the launcher directory:

cd ~/amana-privnet-launcher

Run the launcher script:

python launch_privnet.py

The launcher performs the following actions:

1. Generates validator private keys
2. Creates keystore files for each node
3. Generates the custom genesis file (custom_amana.json)
4. Creates node directories (node1, node2, node3)
5. Generates configuration files for each node

## Compatibility Issues and Fixes

While running the launcher script with the latest QNG version (v2.3.0+dev), a few compatibility issues were found between the launcher and the newer QNG version. These were small differences in paths, flags, and data directories. The following fixes were applied so that the private network could start correctly.

### QNG Binary Path

The launcher script originally expected the QNG binary at:

~/qng/build/bin/qng

However, in this setup the compiled binary was located at:

~/work/qng/build/bin/qng

Therefore the binary path was updated in the launcher script (launch_privnet.py) so that it points to the correct QNG executable.

### Amana Network Flag

The launcher script originally used the flag:

-amana

However, the current QNG version requires:

--amananet

The node startup command generated by the launcher script was updated to use the correct flag.

### Data Directory Structure

The older launcher assumed the blockchain data directory:

data/privnet

However, the current QNG version creates:

data/amananet

The configuration paths were updated in the node configuration files (node1/config.toml, node2/config.toml, and node3/config.toml) so that they match the directory structure used by the newer QNG version.

### Cleaning Old Chain Data

When restarting nodes after modifying the genesis configuration, the following error appeared:

"Chain DB: Need to thoroughly clean up old data"

This happens when old blockchain data conflicts with a new genesis configuration. The issue was resolved by removing the previous chain data directories before restarting the nodes:

rm -rf ~/qng_privnet/node1/data
rm -rf ~/qng_privnet/node2/data
rm -rf ~/qng_privnet/node3/data

After cleaning the directories, the nodes started successfully.

### Deprecated Unlock Flag

During node startup, the following warning appeared in the logs:

"The unlock flag has been deprecated and has no effect"

This suggests that validator signing may be handled differently in newer versions of QNG. This behaviour will be investigated further to confirm how validator accounts sign blocks in the PoA network.
